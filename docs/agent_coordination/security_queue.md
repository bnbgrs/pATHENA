## Verified baseline controls

These controls were inspected so future runs do not repeatedly rediscover them without a relevant code change:

- `ExternalFetchGateway` direct mode rejects loopback/private/link-local/reserved targets and freezes validated DNS results into the socket connection, reducing SSRF and DNS-rebinding risk.
- Tor mode delegates hostname resolution to SOCKS, uses per-request stream-isolation credentials, restricts the proxy endpoint to loopback by default, and fails closed instead of silently falling back to direct networking.
- Direct and Tor HTTPS paths use Python's default TLS context with certificate and hostname validation; no `verify=False` or permissive SSL context was found in the reviewed gateway path.
- Redirects are bounded and re-authorized per hop; response bytes are capped; URL userinfo is rejected; sensitive-looking query values are redacted from recorded provenance.
- Core API listener is hard-coded to IPv4 loopback (`127.0.0.1`), refuses alternate bind hosts, caps request bodies, rejects browser `Origin` requests, and requires a random bearer token using constant-time comparison.
- API runtime publication rejects symlink ancestors, uses exclusive staging files, durable replacement and best-effort cleanup.
- LM Studio configuration rejects non-loopback hosts, credentials, paths, queries and fragments; `SEC-003` tracks the remaining ambient-proxy issue in the adapter transport.
- Protected Content uses pyca/cryptography AES-256-GCM and Argon2id rather than custom primitives, uses random keys/nonces/salts, authenticated decryption and best-effort wiping of mutable key buffers. v1 persisted Argon2id work factors are now capped before KDF construction under `SEC-004`.
- Native DOCX extraction does not extract ZIP members to filesystem paths; it reads only required OOXML parts and applies per-part uncompressed-size and compression-ratio limits before parsing them.
- Backup restore validates absolute/non-overlapping destinations, canonical manifest object paths, object hashes and database integrity; `_safe_existing_file()` resolves source objects beneath the backup target and rejects leaf symlinks.
- Python/build dependencies are exactly version-pinned; the uv lockfile carries artifact hashes and CI invokes locked resolution. `SEC-005` tracks the separate mutable GitHub Action references.

## Handoffs

- `SEC-001`: Windows scripts currently default the runtime root beneath per-user LocalApplicationData and reject repository-local roots, but they verify writability rather than ACL confidentiality. Coordinate with Windows/Release ownership; Security owns the invariant/test and may implement a narrowly isolated ACL helper only with real Windows verification and established Windows APIs.
- `SEC-002`: Feature/Specification decision required before changing the externally visible HTTP(S) contract. Security should not remove HTTP support unilaterally.
- `SEC-003`: Backend owns `LMStudioProvider`; required invariant is that loopback model traffic never uses ambient HTTP(S) proxies. Security should verify the Backend fix with hostile-proxy regression coverage rather than editing the adapter concurrently.
- `SEC-004`: no cross-owner handoff required. Security fix is committed; wait for targeted/CI verification before marking VERIFIED.
- `SEC-005`: Quality owns workflow definitions. Required invariant: executable third-party/official Action code is referenced immutably by reviewed SHA rather than a movable tag; Security should verify the resulting workflow diff but not edit Quality-owned CI concurrently.
- `SEC-006`: Backend owns `BlobStore`; required invariant is that every storage write remains confined beneath its configured spool/archive root even when hostile symlink/junction ancestors are present. Security should supply/verify adversarial filesystem regression cases and avoid concurrently rewriting BlobStore while Backend owns the implementation.
