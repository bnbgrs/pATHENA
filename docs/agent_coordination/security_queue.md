## Verified baseline controls

These controls should not be re-audited without relevant code/dependency/configuration movement:

- `ExternalFetchGateway` direct mode rejects loopback/private/link-local/reserved targets and binds validated DNS results into the connection path; redirects are bounded and re-authorized.
- Tor mode delegates DNS to SOCKS, uses per-request stream-isolation credentials, constrains the proxy endpoint and fails closed rather than silently falling back to direct networking.
- Direct/Tor HTTPS paths use normal certificate and hostname validation; no permissive TLS context was found in the reviewed gateway path.
- Core API is IPv4-loopback-only, bearer-authenticated with constant-time comparison, rejects browser `Origin` requests and bounds request bodies.
- LM Studio configuration rejects non-loopback endpoint configuration; SEC-003 tracks ambient proxy handling in the adapter transport.
- Protected Content uses pyca/cryptography AES-256-GCM and Argon2id, random keys/nonces/salts and authenticated decryption; SEC-004 tracks KDF work-factor bounds.
- Native DOCX reads constrained OOXML parts without extracting archive members to filesystem paths. HTML parsing is bounded and non-executing. PDF parsing is isolated in a supervised child process with input/page/output/time/memory limits.
- Backup restore validates destination isolation, manifest/object paths, hashes and SQLite integrity before publication.
- Python/build dependencies are exact-pinned and locked with artifact hashes; SEC-005 tracks mutable GitHub Action references separately.

## Handoffs

- `SEC-001` -> RELEASE/SECURITY: prove or establish a private Windows DACL invariant for runtime token/discovery state.
- `SEC-002` -> FEATURE: decide whether plaintext HTTP remains part of the intended external-fetch contract.
- `SEC-003` -> BACKEND: make LM Studio's loopback transport explicitly proxy-free and add hostile-proxy regression coverage.
- `SEC-004` -> SECURITY: wait for real targeted/CI execution before VERIFIED.
- `SEC-005` -> QUALITY: pin executable external Actions immutably.
- `SEC-006` -> BACKEND: BE-011's static symlink/reparse protection is only a partial fix; close the check/use race for blob creation/publication using directory/object identity-safe operations.
- `SEC-007` -> BACKEND: apply the same identity-safe confinement to cleanup/purge/orphan-deletion paths; static pre-checks plus later pathname `unlink()` are insufficient against out-of-band parent replacement.
- `SEC-008` -> BACKEND: bound backup deletion-ledger resource consumption before directory materialization/file reads/JSON decoding; corrupted backup targets must fail closed without attacker-controlled memory growth.
- `SEC-009` -> BACKEND/BE-028: migration clone creation, cleanup and activation need identity-bound filesystem operations; static reparse checks alone do not close parent-replacement races.
- `SEC-010` -> BACKEND/BE-028: bound migration-journal bytes before full read/JSON decode while preserving existing no-follow and handle/path identity checks.
