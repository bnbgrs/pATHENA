## Purpose

Expose the durable recovery contract from #490/#491 in the Desktop without inventing partial output or reconstructing request state.

## Implemented

### Candidate discovery

After a persisted chat is loaded:
- Recovery is considered only when the **last persisted message is a user message**.
- The persisted user `message_id` is used as the candidate send-operation ID.
- The Desktop asynchronously asks Core for that exact chat/operation recovery state.
- A completed chat whose last message is an assistant response does not probe recovery.

No operation ID is generated by the UI.

### Recovery presentation

A compact `chatRecoveryBar` remains hidden by default.

If Core returns `can_continue=true`:
- the bar states that a persisted checkpoint exists;
- a **Continue** button is shown;
- Continue invokes `DesktopApiController.continue_chat_operation(...)` with the exact persisted identities.

If Core returns `ambiguous` or `conflict`:
- the bar explains that recovery requires review;
- ATHENA explicitly says it will not repeat the provider call automatically;
- no Continue button is shown.

For `absent`, `complete`, or other non-actionable states, the bar remains hidden.

### Lifecycle

- New chat clears recovery state.
- A completed direct or Grounded response clears recovery state.
- Busy state disables Continue.
- A cancelled Continue schedules a fresh Core recovery inspection.
- Recovery-status read failures do not mutate chat state or fabricate a retry action.

## Tests

Focused Pathena window regressions verify:
1. an incomplete persisted user turn triggers inspection using the exact message ID;
2. the recovery bar stays hidden until Core confirms resumability;
3. `resumable` exposes Continue and invokes the controller with exact IDs;
4. `ambiguous` shows a warning but never exposes Continue;
5. a complete user+assistant thread does not probe recovery.

## Safety boundary

This UI does not make ambiguous provider attempts resumable. It merely consumes the Core `can_continue` decision. The Core remains authoritative.
